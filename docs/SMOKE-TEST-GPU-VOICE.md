## Hello-world acceptance

1. Keep the console on 12.40 and never update above 13.60 for this project. Keep this
   homebrew-only console off PSN. Jailbreaking can cause bans and crashes.
2. Apply the owner-selected jailbreak after each reboot. Confirm its actual loader
   is listening on 9021. Do not substitute an unverified etaHEN binary for 12.40.
3. From the project directory run `bash scripts/build.sh`. Require successful Docker
   image build, upstream SDK sample build, Muse payload builds and gate tests.
4. Set `PS5_HOST` to the actual console LAN IP. Optionally set `PS5_PORT` if the
   installed loader uses another port. Run `bash scripts/deploy-hello.sh`.
5. Expected display: a system notification reading **Muse: hello from your PS5**.
   This hello-world is a notification, not a fullscreen gadget UI.
6. Expected deploy output: JSONL boot and notification records. The latter includes
   the notification API return value. The deploy script saves them automatically
   to `logs/hello-console.log` on the deployment host (Opti3 for the current setup). A loader must support returning stdout;
   silence alone does not prove a crash. Hello-world does not upload to Muse yet.
7. Report whether the notification appeared. The operator reads the saved log;
   the user should not copy/paste log contents. Kernel-level diagnosis can use the
   selected klogsrv build. Record firmware, loader revision and payload hashes.

## Microphone probe (compiled, experimental hardware behavior)

The probe reads two newline-delimited values from stdin: the console's AudioIn
module path and a new writable WAV path. Supply them through `prospero-deploy -i`
using the installed loader. Paths are inputs, never baked into the ELF.
It records approximately three seconds at 48 kHz S16 mono. Speak, then test physical
mute in a second recording. Pull the WAV through the configured FTP service and
listen. Muted/no-device/unknown mute-state grains should be silent. Check both
DualSense and headset behavior and record which device was actually selected.
The probe requires payload-context AudioIn availability; PSBox demonstrates the API
in native-title context, which is not proof the same call works in a payload.

## Concrete native test sequence

1. Finish setup; ensure the bundled models load. Never interpret the host preview's
   fixture FPS as a console result. Capture actual frame pacing, memory behavior
   and local inference latency in the user hardware loop.
2. Hold R2 and say “make me a falling-block puzzle game”; release. Check correct
   transcription and the final Muse plan. Require Muse's compatible /voice JSON
   response contract; missing extensions must show an error, not fabricated plans.
3. While voice_gate_verified is false, say “approve this plan”: no approval POST.
   Hold X before a plan appears: no approval. Release and press X after reviewing
   every page: exactly one approval. Reject corrupted/oversized test artifacts.
4. Repeat with Square and “add a two-player mode.” Muse must receive the parent
   plan ID/revision. It must retain the original game request. If the server lacks
   that schema, the app should fail explicitly instead of discarding the context.
5. Use Triangle to see the phone URL/pairing code. Test WAV upload on LAN HTTP.
   Hold-to-talk only after placing that page behind trusted HTTPS. Wrong tokens,
   a busy gadget and approval attempts from the phone must be rejected.
6. Cancel during draft, approval polling and download. No stale local result may
   launch. An already accepted remote build may finish; there is no cancellation
   endpoint. After dispatch, the UI must state that execution cannot be cancelled.
7. Only after deliberate hardware voice tests, opt into voice_gate_verified in
   the persisted config. Try “what colors will it use?”, “don't approve”, “yes”,
   and “approve if it works”: none may approve. Confirm the three explicit commands
   against the currently displayed plan, physical buttons and both mute states.
8. Disconnect the server during a session and reconnect. Confirm logs reach Muse
   automatically; the JSONL journal stays on disk until a 2xx acknowledgement.
   Muse diagnoses from the latest uploaded journal before asking for user detail.

The app's default structured spool is /download0/muse/logs/pending.jsonl inside
its sandbox. Through FTP the sandbox commonly has a prefix such as
/mnt/sandbox/PPSA99576_000; establish the actual mount on this console. Config can
select another writable log directory. The upstream graphics runtime also keeps
/download0/hui/dev/app.log and app.prev.log. Those raw native diagnostics are an
FTP/kernel-log fallback; they are not a substitute for the automatic JSONL upload.
Generated ELF delivery and native-package installation use separate paths. The
installer helper has its own durable journal so it can retain errors after Muse
is closed during launch handoff. See PACKAGING.md for the installer contract.

## GPU, neural speech and generated native applications

1. Start with `inference_backend: "auto"` and `speech_mode: "neural"` in the
   persisted configuration. Check actual Qwen/Whisper backend records after each
   engine runs. Device selection by itself is not proof that inference succeeded.
   The UI summarizes the engine; uploaded `inference_backend` records include
   device, fallback reason and allocator statistics. Capture real console latency
   and memory pressure while the animated interface remains usable.
2. Exercise `cpu` and `vulkan_required` policies separately. Required Vulkan must
   fail visibly if the backend is unavailable; AUTO can retry returned failures
   on CPU. A fatal driver abort requires restart and recovery. Use `cpu` plus
   `speech_mode: "espeak"` to isolate such a failure, without replacing the package.
3. Speak a short request, then a longer plan. Confirm audible neural replies,
   complete sentences, R2/Circle playback interruption and later transcription/
   drafting after the voice models have been unloaded. The host voice preview is
   a Linux CPU recording, not console audio or a speed target. This implementation
   produces the whole WAV before playback. Confirm eSpeak fallback when neural
   initialization fails and server WAV fallback if all local synthesis fails.
4. Have Muse return a `kind: "pkg"` build with a fresh `PPSA99xxx` title ID,
   matching `IV0000` content ID, exact size and SHA256. The approved request asks
   for a package. The complete package must pass identity/hash checks before the
   helper starts. Corrupt content IDs, digests, truncation and stale generations
   must prevent installation. `.pkg` bytes never go directly to the ELF loader;
   only the bundled installer helper is dispatched there.
5. Verify the helper resolves the same package through actual mount metadata and
   receives its writable journal descriptors, or proves access through the
   verified shared writable-path fallback. Failure of both journal access methods,
   or a failed nonce, package identity or mount probe, must prevent submission.
   Test the default sandbox path and retained logs after a title handoff.
6. Observe submission, progress, ready-to-play status, launch request and a
   matching running-title confirmation as separate results. Playable status can
   precede completion; progress must retain its actual value. Auto-launch must
   wait for completed status and recheck it before handing off the title, so
   Muse's source sandbox stays mounted during copying. A zero submission
   return must never display installation success. A launch request alone must
   never display confirmed execution. Missing permissions/modules/loader and
   native API failures must retain diagnostic codes and upload logs.
7. Repeat with an existing title ID and with Muse's own ID: both must be rejected
   without uninstalling or replacing anything. This version auto-installs new
   generated titles; it deliberately does not update existing applications.
8. Test completed-install launch handoff: the helper must retain its independent
   journal. Disconnect the server, reconnect and reopen Muse if necessary; retained
   installer logs must upload. Separately, close Muse before installation completes
   to test interruption recovery. The helper exits on a pre-launch parent
   disconnect; no automatic resume or launch is promised. The OS may continue,
   but removal of the source sandbox can interrupt copying. Reopen Muse for journal
   recovery and have Muse read those logs before asking the user for details.

These checks remain unperformed until the owner runs them on the Slim. Compatible
12.40 payloads, installation permissions and launch context still need independent
